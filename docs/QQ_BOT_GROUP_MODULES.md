# QQ 机器人按群功能模块管理

更新时间：2026-11-19

状态：P0（机器人侧）和 P1（网页侧范围控制）已实现。权限（群主 + 群管理员，运维锁定）、提示方式（同群同功能 10 分钟一次）、入口（群内 `/模块` + 配置文件）和问一问范围（使用说明常开，其余五项可关）已确认。

## 1. 结论摘要

1. 在机器人进程里增加一份**模块注册表**，把现在散落在 `commands.mjs`、`bot.mjs` 的功能统一登记成“模块 + 指令”两级。
2. 新增按群配置 `state/group-modules.json`：群可以覆盖模块和单个指令的开关，没有配置时完全保持现在的行为。
3. **基本信息常驻**：菜单/帮助、关于、版本、新对话、`/模块`，以及问一问里的“使用说明”。
4. **问一问不整块关闭**：使用说明常驻，临东服资料、公交与线路、公告与运营、地图与地点、通用问答五项可关。
5. 指令类可关：实用工具、群互动、查询指令、账号绑定、B 站解析；进退群提示、玩家进出播报也已按群；指令卡片、回答配图、发言统计采集放第二批。
6. **权限**：本群群主和群管理员可以用 `/模块` 改本群开关；机器人运维通过配置文件设默认值和锁定项，锁定项只能由运维改。
7. 关闭后不静默：第一次触发给一条说明，同群同功能 10 分钟内只提示一次。
8. 权限只影响本群，单聊和网页 `/ask` 不受影响。

## 2. 现状与约束

### 2.1 现状

- 实现前，机器人是独立进程，所有群共用一份 `.env`，只有全局开关：`QQ_BOT_BILIBILI`、`QQ_BOT_CARDS`、`QQ_BOT_IMAGES`、`QQ_GROUP_LINK_ENABLED` 等，群与群之间没有差异。
- 此前唯一的按群配置是 `data/group-notices.json`（入群、被踢、退群文案），用 `QQ_BOT_GROUP_ALIASES` 把官方 openid 映射到旧群号。
- 功能入口分散：本地指令在 `src/commands.mjs`，帮助/新对话/问一问/B 站/卡片/事件在 `src/bot.mjs`。没有统一的注册表，加功能要同时改分发、帮助和文档。

### 2.2 平台与部署约束

- `GROUP_AT_MESSAGE_CREATE` 的 `author.member_role` 由平台下发（`member` / `admin` / `owner`），可直接判断群主和群管理员，不需要额外接口。
  参考：[群@机器人消息](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/group_at_message_create.html)。
- 全量群消息和 OneBot 事件桥也能拿到角色，但全量模式要群主在手机 QQ 单独授权，不能当作默认可用。
- 机器人是个人认证主体，只能进入运维本人任群主或群管的群（2026-11-19 补充）。因此群数量有限、运维一定在群里，开关不构成新的权限边界。

### 2.3 问一问已有的基础

`/api/assistant/chat` 在检索和模型调用之前已经做确定性意图分类（`apps/web/lib/assistant/intent.ts`），并给出 `reasonCode`，例如：

- `public_info.transit`、`public_info.operations`、`public_info.place`、`public_info.map`、`public_info.wiki`
- `server_status`、`site_help`、`smalltalk`、`unknown`
- 账号类 `self_location` / `nearby` / `identity` / `account_data`（群聊本来就会被拦截）

按群控制问一问范围可以直接复用这层分类，不需要新写一套问题分类器。

## 3. 模块清单

模块 id 用于配置文件和 `/模块`；指令 id 沿用 `commands.mjs` 里已有的名字。

### 3.1 常驻（不可关闭）

| id        | 名称      | 覆盖内容                | 不可关闭的原因                 |
| --------- | --------- | ----------------------- | ------------------------------ |
| `help`    | 菜单/帮助 | `/帮助`、`菜单`、`功能` | 成员靠它发现功能；关了无从查起 |
| `about`   | 关于      | `/关于`                 | 说明机器人归属和数据来源       |
| `version` | 版本      | `/版本`                 | 排障要核对机器人和网页版本     |
| `reset`   | 新对话    | `新对话`、`重置`        | 清上下文是止损手段             |
| `modules` | 模块管理  | `/模块`                 | 关了群里没人能恢复             |

### 3.2 问一问

问一问拆成“常驻的使用说明 + 可关的内容范围”。常驻部分保证任何群都能问清楚“这个机器人怎么用、怎么绑定、站内服务怎么找”。

| id               | 名称       | 覆盖的意图/工具                                                                                                                                           | 默认 | 可关 |
| ---------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- | ---- |
| `ask.basics`     | 使用说明   | `site_help`、`smalltalk`、`search_site_content`（服务/FAQ）、`list_material_templates`                                                                    | 开   | 否   |
| `ask.server`     | 临东服资料 | `public_info.wiki`、`server_status`、`search_wiki`、`get_server_status`                                                                                   | 开   | 是   |
| `ask.transit`    | 公交与线路 | `public_info.transit`、公开起终点的 `route`、`search_transit`、`line_timetable`、`journey_plan`、`plan_route`、`query_travel_schedules`、`network_health` | 开   | 是   |
| `ask.operations` | 公告与运营 | `public_info.operations`、`poi_notices`、`service_notices`、`operation_detail`                                                                            | 开   | 是   |
| `ask.map`        | 地图与地点 | `public_info.place` / `place_nearby` / `page_anchor` / `map`、`search_places`、`nearby_places`、`along_line_places`                                       | 开   | 是   |
| `ask.general`    | 通用问答   | `unknown`（没有上下文时的通用知识、闲聊式提问）                                                                                                           | 开   | 是   |

说明：

- 问一问没有总开关，`/模块 关 问一问` 等价于把五个可关范围一起关掉，使用说明保留。
- `ask.server` 关闭后，Wiki 条目、服务器在线状态、进服/规则类资料都不再回答；`/人数` 指令是独立模块，不受影响。
- `search_site_content` 同时覆盖运营公告、服务目录和 FAQ。公告开关关闭后，运营公告那一段会从结果里收窄（第一批先靠意图预检拦截，第二批再在工具内部按范围过滤）。
- `smalltalk`（你好、谢谢、你是谁）始终放行：不检索、不额外调用工具，拦下来只会显得机器人坏了。
- `ask.general` 只拦“没有上下文且分类为 `unknown`”的问题。带历史的追问（“那末班呢”）不拦，避免把正常追问误判成通用问答。
- 路线规划（“从 A 到 B 怎么走”）归 `ask.transit`；关闭后连步行方案也不答，避免同类问题一半答一半不答。
- 群聊里的账号类问题（我在哪、我的票）仍然走现有的“请私聊”预检，不受这套开关影响。

### 3.3 指令与机器人能力

| id             | 名称         | 包含指令/能力                                                         | 默认 |
| -------------- | ------------ | --------------------------------------------------------------------- | ---- |
| `tools`        | 实用工具     | `/随机` `/骰子` `/算` `/电码` `/gb2312` `/天气` `/ip` `/历史` `/对联` | 开   |
| `community`    | 群互动       | `/签到` `/签到榜` `/发言统计` `/发言榜` `/运势` `/重抽`               | 开   |
| `query`        | 查询指令     | `/随机地点` `/人数`                                                   | 开   |
| `link`         | 账号绑定     | `/绑定` `/确认` `/我的绑定` `/解绑`                                   | 开   |
| `bilibili`     | 视频解析     | B 站链接自动回复标题、UP 主、封面                                     | 开   |
| `notices`      | 进退群提示   | 入群欢迎、被踢、退群文案（每群文案继续放在 `group-notices.json`）     | 开   |
| `playerEvents` | 玩家进出播报 | 玩家进服/退服消息广播到本群，事件桥和轮询都生效                       | 开   |

`notices` 和 `playerEvents` 关闭后只影响本群：事件仍然会到达机器人，但不再往这个群发消息。

### 3.4 第二批：呈现与统计

| id            | 名称         | 说明                                           | 默认 |
| ------------- | ------------ | ---------------------------------------------- | ---- |
| `cards`       | 指令卡片     | 本地渲染的 PNG 结果卡片                        | 开   |
| `images`      | 回答配图     | 引用运营内容封面时补一张图                     | 开   |
| `memberStats` | 发言统计采集 | 后台记录群消息，供 `/发言统计`、`/发言榜` 使用 | 开   |

`memberStats` 与 `community` 分开：关掉采集不应该连带关掉签到和运势。这三项还没有按群生效，P2 继续做。

### 3.5 指令级覆盖

模块是批量开关，单个指令仍可覆盖。例如关掉整个 `tools`，再单独打开 `/天气`。配置里保留 `commands` 字段，`/模块` 也接受指令 id。

## 4. 问一问范围控制的实现

### 4.1 传参

机器人只在群聊请求里增加一个不含群 id 的能力位：

```json
{
  "channel": "qq-group",
  "capabilities": {
    "server": true,
    "transit": true,
    "operations": false,
    "map": true,
    "general": true
  }
}
```

网页 `/ask` 不传该字段，行为不变；QQ 单聊不按群配置，沿用默认值。

### 4.2 服务端

在 `apps/web/app/api/assistant/chat/route.ts` 的意图预检之后、检索之前加一层范围判断：

1. `reasonCode` 映射到 `basics` / `server` / `transit` / `operations` / `map` / `general`；
2. 命中已关闭范围时直接返回固定文案（不检索、不调用模型）；`unknown` 的置信度天然是 `low`，按下面第 3 条单独判断，其它范围的 `low` 不拦；
3. `unknown`（通用问答）只在没有历史消息时拦，追问继承上文；
4. 允许的工具按范围过滤：`buildOpenAiToolDefinitions` 增加允许范围的参数，工具定义补一个 `scope` 字段；
5. 系统提示追加一句“本群只开放以下范围……被关闭范围的问题直接说明未开启，不要用常识代答”。

固定文案示例：

- 公交关闭：`本群未开启「公交与线路」问答。群主或管理员可以 @我 发送 /模块 开启。`
- 全部可关范围都关：`本群只保留问一问的使用说明，公交、公告、地图和通用问答需要群主或管理员开启。`

### 4.3 机器人侧处理

服务端直出的 SSE 会带 `meta.routing.reasonCode`（例如 `group_scope.transit_disabled`）。机器人拿到后：

1. 按 reasonCode 映射回模块 id，用本地配置生成文案：锁定项提示“该项由机器人管理员锁定”，未锁定项提示可以用 `/模块` 开启。服务端的固定文案只作为其他客户端的兜底。
2. 同群同模块 10 分钟内只发一次；被节流的请求不再发送任何消息，也不写入对话历史。如果“正在查资料”已经发出去，本次仍然发送说明，避免出现提示后没有下文。
3. 只有群里有问一问范围被关闭时才延迟先发提示（默认 1 秒）：正常回答仍会看到“正在查资料”，被范围拦截的秒回不会先提示。
4. 这类回复不触发卡片、配图、二次精炼。

### 4.4 已知取舍

- 意图分类是确定性规则，不是百分之百准确。误判成 `unknown` 的公交问题，如果 `general` 开着仍可能被回答；误判成公交的通用问题会被拦。取舍是“宁可说明未开启，也不静默答错”。
- 关闭公交不等于模型完全不知道公交：提示词会要求不答，但不能保证模型永远不提。需要更强保证时，下一批再加“按引用来源过滤”的兜底。
- 范围控制只作用于问一问；不做关键词改写，也不拦截本地指令。

## 5. 数据模型

### 5.1 文件

默认路径 `state/group-modules.json`，可用 `QQ_BOT_GROUP_CONFIG_PATH` 改。

放在 `state/` 而不是 `data/`，是因为部署更新会覆盖 `src/`、`data/`，只保留 `.env` 和 `state/`。默认值写在代码注册表里，配置文件只存覆盖项，升级不会冲掉运维改过的开关。

### 5.2 结构

```json
{
  "version": 1,
  "defaults": {
    "modules": { "bilibili": false },
    "commands": {}
  },
  "groups": {
    "<group_openid 或旧群号>": {
      "name": "临东公交交流群",
      "modules": {
        "ask.server": true,
        "ask.transit": false,
        "ask.operations": true,
        "tools": true
      },
      "commands": { "weather": false },
      "locked": ["ask.transit"],
      "updatedAt": "2026-11-19T12:00:00+08:00",
      "updatedBy": "role:admin"
    }
  }
}
```

- 群 key 优先 `group_openid`，也接受 `QQ_BOT_GROUP_ALIASES` 里的旧群号，解析顺序与 `group-notices.json` 一致。
- `defaults` 只影响没有显式配置的群，方便统一收紧新群。
- `locked` 里的模块/指令只能由运维改，群管理命令会提示“该项由机器人管理员锁定”。
- 每群限流还是全局配置，按群限流放在 P2。

### 5.3 解析优先级

单个功能的最终状态取第一个命中项：

1. `groups[key].commands[id]`
2. `groups[key].modules[moduleId]`
3. `defaults.commands[id]` / `defaults.modules[moduleId]`
4. 注册表默认值

再和全局 `.env` 开关取交集：`QQ_BOT_BILIBILI=0` 这类运维级关闭始终优先，群不能把它打开。

### 5.4 写入与热加载

- 机器人是唯一写入者（第一批没有网页后台），写入用“临时文件 + rename”。
- 读取后缓存，按文件 mtime 判断是否重载，最多每秒 stat 一次。
- 文件不存在：使用注册表默认值，行为与现在完全一致。
- 启动时 JSON 损坏或字段非法：记 warn，跳过非法项用默认值，进程不退出；运行中被写坏时保留上一份可用配置，`--check` 能列出问题。

### 5.5 审计

每次开关写入一行到 `state/module-audit.jsonl`，按大小轮转。字段：时间、群（打码 openid）、对象、旧值、新值、操作者角色、操作者昵称、操作者 openid（打码）。日志和回复里都不出现完整 openid。

## 7. 权限

### 7.1 身份来源

只用事件里的平台字段，不接受消息文本自报身份：

- 官方事件：`data.author.member_role`（`owner` / `admin` / `member`）；
- 事件桥：OneBot 的 `sender.role`，第二批支持。

落地前先用真实日志确认线上事件确实带 `member_role`（官方文档已包含该字段）。

### 7.2 权限矩阵

| 操作                       | 群成员 | 群管理员 | 群主 | 机器人运维 |
| -------------------------- | ------ | -------- | ---- | ---------- |
| 查看 `/模块`、帮助里的开关 | 允许   | 允许     | 允许 | 允许       |
| 开关未被锁定的模块/指令    | 拒绝   | 允许     | 允许 | 允许       |
| 开关被锁定的模块/指令      | 拒绝   | 拒绝     | 拒绝 | 改配置文件 |
| 改默认值、白名单、限流     | 拒绝   | 拒绝     | 拒绝 | 改配置文件 |
| 看审计记录                 | 拒绝   | 拒绝     | 拒绝 | 读日志文件 |

### 7.3 兜底

- `member_role` 缺失或未知：拒绝修改，回复“暂时无法确认你的群身份，请联系机器人管理员”；查看仍允许。
- `QQ_BOT_MODULE_ADMINS` 可配 `群openid:成员openid` 白名单，作为平台字段缺失时的临时通道，默认留空。
- 关闭 `modules` 模块的请求直接拒绝，避免把自己锁死。
- 开关操作单独限流：每人 5 次/分钟、每群 20 次/分钟。

### 7.4 为什么是群主 + 群管理员

1. 平台原生字段，零配置，不需要绑定账号或维护名单；
2. 他们本来就能移除机器人，开关不是更大的权力，风险边界没有变化；
3. 个人认证约束决定运维一定在群里，误关可以当场纠正；
4. 运维可能只是群管而不是群主，“仅群主”反而不覆盖运维本人；
5. 比“只有运维能改”少一层日常沟通成本。

### 7.5 考虑过但不采用

- **必须绑定临东通账号**：群绑定只覆盖已绑定成员，运维自己也未必绑；权限边界没有变强，却多一步操作。
- **只有运维能改**：需要额外申请通道，群数量少时收益不明显。
- **网页后台**：机器人是独立进程，配置要跨进程同步；第一批用群内命令 + 配置文件更直接。需要批量管理或审计看板时再做。

## 8. 交互

### 8.1 命令

| 用法                | 说明                                 |
| ------------------- | ------------------------------------ |
| `/模块`             | 列出本群模块状态，标注被运维锁定的项 |
| `/模块 关 问一问`   | 关闭问一问的五个可关范围             |
| `/模块 关 公交`     | 只关公交与线路问答                   |
| `/模块 开 天气`     | 打开单个指令                         |
| `/模块 详情 问一问` | 看各范围的状态、包含内容和最后修改人 |
| `/模块 恢复默认`    | 清除本群覆盖                         |

`/模块` 展示示例：

```text
本群功能
问一问
  · 使用说明      常开
  · 临东服资料    关
  · 公交与线路    开
  · 公告与运营    关
  · 地图与地点    开
  · 通用问答      开
指令
  · 实用工具      开（部分）
  · 群互动        开
  · 查询指令      开
  · 账号绑定      开
  · 视频解析      关
  · 进退群提示    开
  · 玩家进出播报  关
群主或管理员可发送「/模块 关 天气」「/模块 开 公交」调整。
```

保留 `/功能`、`菜单` 作为帮助的别名，不给“模块”复用，避免和现有自然触发词冲突。

### 8.2 关闭后的提示

- 指令：`「天气」在本群未开启。群主或管理员可以 @我 发送 /模块 开启。`
- 问一问范围：`本群未开启「公告与运营」问答。群主或管理员可以 @我 发送 /模块 开启。`
- 节流：同群同功能 10 分钟内只提示一次，其余静默；`QQ_BOT_MODULE_HINTS=0` 可全部关闭。
- 帮助里单列“未开启的功能”，成员能看出是配置问题，不是机器人坏了。

### 8.3 变更反馈

开关变更后短回复确认，并提示恢复方式：`已关闭本群的「公交与线路」。发送「/模块 开 公交与线路」可恢复。`

`GROUP_ADD_ROBOT` 先把新群写进日志，第二批再发一次性说明。
