# 控件清单与展示板

入口为 `/dev/controls`。开发环境开放；生产环境仍需显式设置 `NEXT_PUBLIC_ENABLE_CONTROLS=1`。

## 覆盖范围

`pnpm ui:controls:sync` 使用 TypeScript AST 扫描 `apps/web/app`、`apps/web/components` 和 `apps/web/lib`，从每个业务页面沿导入、动态导入和布局边界收集源码节点。扫描不执行登录判断，因此后台及条件分支中的 JSX 都会进入清单。独立部署的 `apps/portal` 不属于该应用。

清单包括交互控件、组件引用和带样式的容器。循环生成的多个实例合并为源码节点，节点数不等于独立控件种类数。模块依赖分析采用保守口径：同一模块的其他导出也可能列入相关页面；动态拼接的类名、运行时数据状态、外部组件内部实现和浏览器视觉效果不能仅由静态清单证明。

展示板按页面、类型、源码和预览状态筛选。动态路由显示路径模板；固定路由可打开业务页，并继续遵守原业务权限。

## 一致性约束

`controls-registry.json` 同时维护目录和共享预览登记。共享组件需要同时被业务页面与展示板引用、渲染，不能仅导入后闲置。

- `SegmentedControl`：分段按钮共用选中语义；页签模式支持方向键、Home、End 和跳过禁用项。
- `MapLayerToggle`：地图业务和展示板共用相同 DOM，预览保留真实 `.map-layer-panel` 材质容器。
- `ScheduleStopTimeTable`：后台运行图、班次编辑和只读展示共用表格。业务层继续处理停车分钟引起的排点变化。
- `RangeInput`、`RouteModeToggleList`、`PoiFacilityEditor`、`WorldCoordinatePicker`、`OperationTableOfContents`：展示板直接调用业务组件。
- 原有手写样例仍可用于对照，但不计作共享组件预览。其他专用编辑器保留为“源码登记，待共享预览”，不宣称已完成视觉验收。

`pnpm ui:controls:check` 检查清单与源码是否一致、分区锚点是否唯一、业务输入类型是否都有展示入口、共享预览的引用是否有效，以及明确登记的共享 DOM 类名是否再次被复制。Web 构建执行此检查；页面或控件变化后先运行同步命令，再检查清单差异。生成内容为 UTF-8 无 BOM，不包含业务记录和用户数据。

## 数据与事件

公开数据由展示板的读取按钮按需请求，使用现有交通方式、班次和地图地点 GET 接口；错误、超时和空数据分别保留状态，不回退到模拟业务记录。班次时刻、地点坐标和设施以只读形式展示，文件输入仅保留本地选择，不上传。

业务组件不导入对话框实现。展示板沿用 `yct:dialog-requested` / `yct:dialog-resolved`，通过 `presentation: 'in-app'` 请求站内确认框或同源页面窗口。原业务调用默认仍由宿主环境决定呈现方式，事件 Payload 不变，详见 `EVENT_SCHEMA.md`。

请求状态为：未加载 → 读取中 → 数据就绪或错误；再次读取会取消旧请求，旧响应和组件卸载后不再更新状态。确认弹窗沿用请求排队、结果派发和生命周期取消逻辑。

## 验收重点

1. 新增或删除业务控件后，未同步的清单应阻止构建；新增源码节点应能按所属页面检索。
2. 页签用键盘切换时，焦点与选中状态保持一致，并跳过禁用项。
3. 后台修改停站、到达、出发和停车分钟时仍走原回调；展示板的真实班次不可编辑。
4. 检查亮暗主题、三档材质、窄屏、输入禁用/只读/错误状态以及真实浮层容器；静态清单不替代这一步。
5. 公开接口失败、超时、重复读取或离开页面时，不显示虚构记录、不保留过期响应；弹窗关闭后焦点应恢复。

本轮没有新增测试文件。后续优先将清单中“待共享预览”的专用控件逐项提取，避免继续增加展示板专用副本。
