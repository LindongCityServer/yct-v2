# 问一问（/ask）信息覆盖缺口

更新时间：2026-11-17

本文只盘点“站内已经有、但问一问拿不到”的信息。问一问的检索和工具清单在
`apps/web/lib/assistant/retrieval.ts` 与 `apps/web/lib/assistant/tools/`，MCP 复用同一份工具。

## 已经覆盖

| 信息                                     | 入口                                                             |
| ---------------------------------------- | ---------------------------------------------------------------- |
| 运营公告、提醒、内容流与正文             | 预检索 + `search_site_content` / `get_operation_detail`          |
| 服务目录、常见问题、社交入口             | 预检索 + `search_site_content`                                   |
| 地图地点、分类、周边、沿线               | 预检索 + `search_places` / `nearby_places` / `along_line_places` |
| 公交、地铁、有轨电车线路与站点           | 预检索 + `search_transit`                                        |
| 首末班、下一班、特殊班次                 | `line_timetable`                                                 |
| 客运班次、起终点换乘                     | `plan_journey` / `query_travel_schedules`                        |
| 地图路线规划（步行、公交、驾车等）       | `plan_route`                                                     |
| 地点公告、客运停运/调整公告              | `poi_notices` / `service_notices`                                |
| 线网数据健康                             | `network_health`                                                 |
| Wiki 检索                                | `search_wiki`                                                    |
| 物料模板清单与工作台操作说明             | `list_material_templates` + 页面指南                             |
| 页面功能说明、界面图例、路线/地图操作    | 页面指南与 UI 指南                                               |
| 点名玩家的位置（不给在线状态、不列全量） | 预检索 + 玩家位置快照                                            |
| 当前登录账号绑定的最后位置               | 预检索                                                           |
| 问一问彩蛋资料                           | 彩蛋提示词                                                       |

## 没覆盖的公开信息

### 1. 服务器状态与在线玩家数

这是最明确的一处缺口：

- 站内接口 [`/api/operations/server-status`](../apps/web/app/api/operations/server-status/route.ts)
  已经返回 `availability`（online/offline/unknown）、`checkedAt`、`latencyMs` 和
  `onlinePlayerCount`。
- 这个接口没有注册成问一问工具，也不在 `/api/v1/public` 里；`/ask` 问“服务器现在开着吗”
  “在线多少人”时只能回答不知道。
- 玩家位置接口 [`/api/map/player-locations`](../apps/web/app/api/map/player-locations/route.ts)
  会返回带 `presence` 的玩家标记；但问一问的玩家检索
  （`apps/web/lib/assistant/player-retrieval.ts`）是**故意**只返回被点名玩家的位置，
  不返回在线状态，也不提供“列出所有在线玩家”。

建议：

1. 新增只读工具 `server_status`，只返回可用性、检查时间和聚合在线人数；
2. 需要的话把它补进 `/api/v1/public`，但不要返回玩家名单；
3. 问一问只回答聚合人数，不回答“谁在线”。

### 2. 更新日志与版本说明

- `apps/web/release-notes.json` 保存了完整发布说明，站内有更新日志页面；
- 问一问的检索和工具都没有读取它，MCP 也没有；
- 用户可以问“最近更新了什么”，现在只能回答不知道。

建议：增加一个 `search_release_notes` 只读工具，按版本和关键词返回摘要。

### 3. 电报工具的码表与资费

- `/services/telegraph` 有完整的中文电码转换、计费、拍发和收报流程；
- 问一问只有页面指南（`ui-guide.ts` 的 telegraph 条目），不能替用户算资费或转电码；
- QQ 机器人已经用站内码表实现了 `/电码`，但网页版问一问没有对应工具。

建议：把电码转换和资费计算抽成只读工具，问一问和 QQ 机器人共用。

### 4. 物料模板的预览信息

- `list_material_templates` 只给模板名称、说明和工作台入口；
- 模板的具体字段、预览图、可填示例没有进入问一问上下文；
- 用户问“某模板长什么样/要填哪些字段”时只能回答大概。

建议：在模板工具里补字段清单和预览图 URL（如果以后做图片回复）。

### 5. 地图测量

- 地图有测距/测量面板，页面指南有说明；
- 没有类似 `plan_route` 的数值测量工具，问一问不能替用户算两点距离或面积。

建议：如确有需求，再加只读测量工具；否则保持页面指南即可。

### 6. 玩家实时在线状态

- 玩家位置接口返回 `presence`，但问一问刻意不暴露；
- 这是隐私取舍，不建议为了“玩家数”把在线名单开放给问答。

## 不应该进入问一问的私有数据

以下数据即使站内存在，也不应注册成问一问或 MCP 工具：

- 账号、登录会话、服务器账号验证结果；
- 后台审核记录、物料审计、分析事件、投稿队列；
- 票务订单、乘车人信息、支付状态；
- 内部任务、调度日志、上传临时文件；
- 未发布草稿、审核中的内容和后台管理数据。

这些数据的读取需要登录态和角色校验，问一问目前以匿名只读为主，不能为了覆盖率破坏边界。

## 建议优先级

| 优先级 | 缺口                      | 理由                                   |
| ------ | ------------------------- | -------------------------------------- |
| P0     | 服务器状态 + 聚合在线人数 | 接口已存在，用户高频会问，且不涉及隐私 |
| P1     | 更新日志                  | 纯公开读模型，接入成本低               |
| P1     | 电报码表与资费            | 站内已有完整逻辑，适合抽成共享工具     |
| P2     | 物料模板字段/预览         | 依赖模板数据结构，收益中等             |
| P2     | 地图测量                  | 使用频率不确定，先保留页面指南         |

QQ 机器人这边已经先补了电码、天气、IP、历史等本地能力；服务器状态和更新日志如果要“两边都通”，
更合适的做法是先在网页端补工具，再让机器人通过 `/ask` 复用，而不是各写一套。
