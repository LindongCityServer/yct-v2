# 服务器与玩家在线状态检测

服务器状态 API、玩家位置 API 和内部玩家同步任务共用检测逻辑。仅调整后端状态逻辑，不新增页面或浏览器第三方请求。

## 检测顺序

1. 优先请求 `YCT_MARKER_BDSLM_BASE_URL` 的 `/api/getPlayerMarkers`。这是现有网页地图 HTTP 端口的可用性及玩家数据检查，不拿静态瓦片 CDN 是否在线判断游戏服务器。
2. 地图成功即具备原有在线基准，再并行请求配置的 Bedrock 状态来源（默认仅 mcstatus.io），确认 MCBE UDP 游戏地址。第三方在线时保持原有地图延迟、人数和正常展示，不用第三方玩家计数替换地图名单。
3. 地图失败时服务器状态为“未知”，不改变任何已记录玩家状态：保留最后已知的在线/离线、最后坐标、`lastSeenAt`、最后成功同步时间，不批量写 `offlineSince`，也不发布下线事件。地图成功但第三方明确离线时，须先满足离线确认窗口（默认 5 分钟）才把玩家持久化为 `offline`；窗口未到返回“未知”并保持玩家状态。
4. 通过现有 API `meta.message` 返回“地图服务暂不可用，状态未知”或“外网离线，不可访问”等原因。地图现有数据源说明会读取该消息；首页沿用原有“未知/离线”展示，不改组件或 CSS。

| 地图玩家接口 | 第三方结果                                 | 对外结果与玩家处理                                  |
| ------------ | ------------------------------------------ | --------------------------------------------------- |
| 失败         | 不调用                                     | 未知（`unknown`），玩家状态原样保留，不产生下线事件 |
| 成功         | 在线                                       | 在线，按本次地图名单更新玩家                        |
| 成功         | 明确离线且已满足确认窗口                   | 外网离线、不可访问，所有玩家离线                    |
| 成功         | 明确离线但确认窗口未到                     | 未知，玩家状态原样保留                              |
| 成功         | 超时、限流、HTTP/JSON 错误、无效或过期观测 | 未知，保持地图在线基准，消息说明尚未完成外网确认    |
| 成功         | 检测失败，且此前明确外网离线尚未恢复       | 保持离线，保持期限内等待第三方新在线证据            |

地图暂时故障不会抹除此前未解决的外网离线记录。第三方报告在线后，立即按地图实际名单恢复。若第三方持续故障，离线确认默认保持最多 5 分钟（从提供方 retrieved_at 计），超过期限且地图正常时恢复以地图结果为准，并通过 API 消息说明尚未完成外网确认。只有新的明确离线观测才续期；未知结果、复用同一提供方缓存或地图失败不续期。旧快照无确认时间时，以其上次尝试时间锚定一次，避免无限保持。

## 配置

```dotenv
# 网页地图 HTTP 服务；与 MCBE 游戏端口不同
YCT_MARKER_BDSLM_BASE_URL=http://ld.cmsy.xyz:19136
YCT_MARKER_BDSLM_TIMEOUT_MS=6000
# 用户确认的 MCBE UDP 游戏地址
YCT_BEDROCK_SERVER_ADDRESS=ld.cmsy.xyz:19132
YCT_BEDROCK_STATUS_TIMEOUT_MS=2000
# 设为 false 时不调用第三方、不采用第三方离线判定，恢复按地图结果判断
YCT_BEDROCK_STATUS_ENABLED=true
# 第三方故障时，最近一次明确离线最多保持多久；0 表示不保持
YCT_BEDROCK_OFFLINE_HOLD_MS=300000
# 按顺序尝试的第三方来源；留空等价于只使用 mcstatus
YCT_BEDROCK_PROVIDERS=
# 单个来源失败后的重试次数与指数退避（重试共享该来源的超时预算）
YCT_BEDROCK_PROVIDER_RETRIES=0
YCT_BEDROCK_PROVIDER_BACKOFF_MS=250
# 连续失败多少次后临时跳过该来源（熔断），以及跳过时长；0 表示不熔断
YCT_BEDROCK_PROVIDER_FAILURE_THRESHOLD=3
YCT_BEDROCK_PROVIDER_COOLDOWN_MS=60000
# 全部来源明确离线时要求的最短持续确认时长（默认 300000 = 5 分钟）
# 窗口未到时返回 unknown，不把地图仍有在线的玩家判为离线；0 表示立即生效（有单源误报风险）
YCT_BEDROCK_OFFLINE_CONFIRM_MS=300000
```

### 多来源配置

`YCT_BEDROCK_PROVIDERS` 为逗号分隔的来源列表，地图确认可用后**并行**探测，按以下规则聚合：

| 各来源结果                       | 对外结果                                    | 记录                     |
| -------------------------------- | ------------------------------------------- | ------------------------ |
| 任一来源明确在线且无冲突         | 在线                                        | 无                       |
| 在线与离线冲突                   | 按事件时间新鲜度判定，见下                  | 标记 `degraded=conflict` |
| 全部来源都明确离线               | 离线（`OFFLINE_CONFIRM_MS` 可要求持续确认） | 无                       |
| 无来源在线，且部分离线、部分失败 | 未知                                        | `degraded=insufficient`  |
| 全部来源失败或熔断跳过           | 未知                                        | `degraded=all-failed`    |

“未知”统一交给离线保持策略：此前已确认外网离线则继续保持在期限内，此前在线则保持地图在线基准，不会因为来源失败而误判在线或离线。超时、限流、非 2xx、JSON 非法或时间戳过期的来源记为失败，不作为离线证据。

冲突时按**事件时间新鲜度**而不是来源固定顺序判定：带来源自身时间戳的观测优先于无时间戳观测；双方都有时间戳时取更新时间较新者；双方都无时间戳时保守保留在线，避免仅凭上游缓存把服务器判为离线。因此 mcsrvstat（无 `retrieved_at`）的“在线”不会覆盖 mcstatus 更新的离线证据。

每个来源连续失败达到 `YCT_BEDROCK_PROVIDER_FAILURE_THRESHOLD` 次后熔断，在 `YCT_BEDROCK_PROVIDER_COOLDOWN_MS` 内跳过该来源，到期后自动半开重试，成功即恢复。降级与熔断会打印一次 JSON warning（含地址、原因、各来源结果），便于排查。

可用的公共 Bedrock 来源只保留实测可用者：mcstatus.io 与 mcsrvstat.us。mcapi.us 的 Bedrock 路径返回 404 且 Java 接口超时，minetools 仅 Java 且当前超时，mcping.net 已跳转至无关站点，均未写入代码。两者均无 API key、免费；mcstatus 官方限流 5 次/秒/IP，mcsrvstat 缓存 5 分钟。默认仍只启用 mcstatus，接入第二来源需显式配置。

| 写法                                     | 含义                                                                                                                         |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `mcstatus`                               | 内置 mcstatus.io Bedrock v2（默认，未配置时的唯一来源）                                                                      |
| `mcsrvstat`                              | 内置 mcsrvstat.us Bedrock；响应无时间戳，观测时间取本次请求时刻，有效期 15 秒                                                |
| `自定义id@https://host/status/{address}` | 自建或代理来源，JSON 按 mcstatus 兼容格式解析（`online` 必填，时间戳可选），`{address}` 会被 URL 编码，可选 `{timeout}` 秒数 |
| `来源#2000`                              | 追加 `#毫秒` 为该来源单独设定超时（100–10000ms）；仍受全局 `YCT_BEDROCK_STATUS_TIMEOUT_MS` 封顶，避免拖慢首页 SSR            |

配置项为空时保持原有行为（仅 mcstatus、全局超时）。条目非法或全部条目不可用时打印一次 warning 并回退到内置 mcstatus，避免线上检测整体失效。重试次数默认 0（不改变原有最坏耗时）；开启后每次尝试共享该来源的超时预算，不会因重试而突破预算。

游戏地址默认使用上述值，可通过环境变量替换。默认来源的 API 域名固定为 `api.mcstatus.io`，只向第三方提交游戏连接地址，不上传玩家名字或位置。HTTP 超时默认 2 秒，限制在 100–10000ms；来源级 `#毫秒` 不能突破该全局预算。第三方内部探测参数根据预算缩短，默认 1.5 秒，为 HTTP 通信留出时间。

离线保持期限 `YCT_BEDROCK_OFFLINE_HOLD_MS` 默认 300000ms，允许 0–300000ms；离线确认窗口 `YCT_BEDROCK_OFFLINE_CONFIRM_MS` 默认 300000ms，允许 0–3600000ms。设为 0 会恢复“明确离线立即生效”，并打印一次误判风险告警。关闭第三方判定不会绕过地图故障的“未知”处理。

## 缓存与限制

同步结果沿用 8 秒进程内缓存，同配置的并发调用合并。第三方确认另缓存最多 30 秒，且不超过提供方 `expires_at` 或观测时间后 120 秒；检测器错误只短暂缓存 8 秒。过期、明显未来的时间戳和超过 120 秒的观测均视为未知，不当作离线证据。

mcstatus.io 本身有缓存和按 IP 的速率限制，参考[官方接口文档](https://mcstatus.io/docs)。一次在线/离线确认反映第三方观测点的可达性，不能保证所有网络均一致；状态变化受提供方缓存、本地缓存及页面原有轮询间隔影响，并非实时承诺。多个独立应用进程各自缓存；大量副本部署时应统一后台探测或共享缓存。

地图和第三方检测完成后返回同一次 API 结果，不增加前端请求阶段；多个来源并行探测，单来源最坏耗时仍受其超时预算约束。未确认外网离线时，第三方检测器故障不会单独把正常地图判为离线。

### 多实例写入

玩家位置快照是单文件 JSON，读改写曾只在单进程内串行，多实例并发会丢更新。现在的写入路径：

1. 进程内 `enqueueMutation` 串行，避免同一进程内多个请求交叉读改写；
2. 跨进程锁文件 `{snapshotPath}.lock`：以 `open(..., 'wx')` 排他创建，写入完成后删除；抢锁失败按 25ms 重试，2s 超时后报错；锁文件 mtime 超过 10s 视为崩溃残留并清除；
3. 临时文件 + `rename` 原子替换快照，快照内 `revision` 每次写入递增，便于排查丢失更新。

部署形态说明：仓库未提供容器编排或多主机共享存储配置，实际形态是**同机一个或多个 Node 进程共享同一 `YCT_PLAYER_LOCATION_STORE_PATH`**，锁文件对该场景有效。若将来跨主机共享 NFS/对象存储，同一把 `.lock` 文件不保证跨主机原子，需改用数据库或单实例写入服务；此时 `revision` 可用于检测覆盖写入。

## 事件与时间语义

沿用原实现顺序：先发布 `PlayerLocationsObserved`，再逐个发布 `PlayerLocationPresenceChanged`；服务器状态发生切换时随后发布 `ServerStatusObserved`。原 main 也采用这一顺序，本次不改动该契约。

`lastAttemptAt` / 故障 `observedAt` 表示本次检测完成时刻；`externalOfflineConfirmedAt` 单独保存第三方 `retrieved_at`，用于保持期判断，不以每次失败请求的完成时间续期。
