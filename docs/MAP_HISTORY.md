# 历史瓦片版本配置

历史地图的数据由运维人工归档：把某一期的瓦片快照放到独立目录（或独立静态站点），
再在本仓库的环境变量里登记一条版本。服务端只读取登记过的版本，客户端无法自造版本。

配置入口：`YCT_TILE_HISTORY_VERSIONS`，值为 JSON 数组。示例见 `.env.example`。

## 版本粒度

粒度由运维决定（推荐按年份或季度），但每条版本必须提供：

| 字段            | 说明                                                                                                  |
| --------------- | ----------------------------------------------------------------------------------------------------- |
| `id`            | 稳定标识，仅小写字母、数字、连字符，最多 64 字符；进入 URL 与缓存键。**发布后不能改**。               |
| `name`          | 展示名称，例如「2024 年初」。                                                                         |
| `worldDataDate` | 世界数据日期 `YYYY-MM-DD`；**确实未知时必须写 `null`**，不能用归档/上传日期代替。                     |
| `dateNote`      | 可选补充说明，例如「仅覆盖主城」。                                                                    |
| `tileTemplate`  | 该快照的瓦片模板，必须包含 `{x}`、`{y}`、`{z}`；支持 `{xd}`、`{yd}`。仅服务端使用，不会下发给客户端。 |
| `coverage`      | 快照覆盖的世界矩形：`minX`、`minZ`、`maxX`、`maxZ`。视口/瓦片超出覆盖范围时直接留空，不发请求。       |
| `zoomRange`     | 该快照可用的瓦片缩放范围 `minZoom` / `maxZoom`。超出时切换会收拢并提示。                              |
| `status`        | `active` 或 `archived`；`archived` 不再出现在选择列表，也不再被代理服务提供。                         |

排序与切换：日期已知的 `active` 版本按 `worldDataDate` 升序，日期未知的版本排在最后，
且不参与「上一期/下一期」。首尾没有相邻版本时按钮禁用。

## 缺数据与不回退

历史模式只渲染所选版本自己的瓦片：

- 瓦片不存在或上游失败时，`/api/map/tile-proxy` 返回 `404` + `X-YCT-Tile-Empty`，
  前端显示斜线占位并提示缺失数量；
- 不会把当前地图瓦片作为兜底，也不会请求当前瓦片；
- 超出 `coverage` 的区域不请求，显示为空白底色。

## URL、缓存与分享

- `GET /api/map/tile-proxy?version=<id>&z=...&x=...&y=...`：`version` 优先于 `source`；
  未知、格式非法或已下架的版本一律返回 404，绝不回退当前瓦片。
- 历史瓦片响应带 `Cache-Control: public, max-age=31536000, immutable`，
  `ETag` 形如 `W/"yct-history-<id>-<upstream>"`，不同版本永远不同。
  缺图响应为 `Cache-Control: no-store`，避免空图被长期缓存。
- 最近视口不再使用 `regionIndex`（它描述当前地图），只按版本 `coverage` 裁剪。
- 分享链接：`/map?hv=<id>&hx=<x>&hz=<z>&hzoom=<zoom>`。坐标保留 1 位小数；
  打开链接后首次解析一次，之后视图稳定时同步回地址栏。版本不存在/已下架会回到当前地图
  并显示提示，非法视图参数会回到默认视图并显示提示。
- 未登录用户与登录用户读取同一份服务端版本清单，链接结果一致；版本选择不写入 localStorage。

## 运维检查清单

1. 快照目录完整、模板能直接取到图片（404 应为真实缺失，而不是路径写错）。
2. `worldDataDate` 与快照实际数据日期一致；不确定就写 `null`。
3. `coverage` 与快照范围一致，避免把大片空白算进覆盖区。
4. `status` 置为 `archived` 前，确认旧分享链接可以接受回退到当前地图。
5. 发布后检查 `/api/map/tile-providers` 的 `history` 数组与日志中的配置告警。
